# Przekazanie pracy: pokaz PL/EN

## Cel

Przygotować prywatny pokaz Strażnika Tajemnic z dwiema przygodami: polską „Cień nad Prabutami” i angielską „Englewood Murder Castle”. Pokaz ma demonstrować klimat, ciągłość kontekstu i deterministyczną mechanikę bez dopowiadania niepotwierdzonych skutków.

## Gałąź i kod

Praca znajduje się na gałęzi `codex/two-quicksetup-integration`; runtime aplikacji jest w `_tester/_base/.silnik/`. Zmiany obejmują integrację teczek przygód, stan świata i ekwipunek, obsługę tur i rzutów, pamięć oraz zapis kampanii, prompt MG i narrację PL/EN, handouty, ograniczenie Quick Setup do dwóch przygód oraz lokalny pakiet do prób.

Gałąź jest robocza i nie została scalona do `main`. W chwili zapisu `origin/main` miał trzy nowsze commity; ich zmiany nakładają się na część plików runtime, więc nie włączyłem ich automatycznie do tego checkpointu. Przed aktualizacją gałęzi sprawdź `git log` i rozwiąż nakładki świadomie. Przed dalszymi zmianami sprawdź też `git status`; nie zakładaj, że lokalne pliki ignorowane lub raporty z `/private/tmp` są dostępne na drugim komputerze.

## Ostatnie udokumentowane sprawdzenia

- Raport lokalny z 21 października zapisał przejście `npm run qa` (362 zestawy, 4024 testy) i kompilacji produkcyjnej.
- Test szybkiego startu w przeglądarce przeszedł dla PL i EN. Test zapisu/wczytania interfejsem używał atrap narracji.
- Nie ma potwierdzonej pełnej rozgrywki z prawdziwymi odpowiedziami modelu ani pomiaru czasu odpowiedzi w wymaganym przedziale 3–5 sekund. Nie traktuj testów z atrapami jako dowodu poprawnej narracji.
- Manifest mediów Prabut oznacza `humanApproval: pending`; obejrzyj handouty przed uznaniem ich za zatwierdzone materiały pokazu.

Wyniki z ignorowanych katalogów testowych i `/private/tmp` nie są częścią gałęzi. Przed pokazem odtwórz potrzebne kontrole na aktualnym commicie. Nie wykonuj płatnych wywołań modelu bez osobnej decyzji użytkownika.

## Start na nowym komputerze

```bash
git fetch origin
git switch --track origin/codex/two-quicksetup-integration
cd _tester/_base/.silnik
npm ci
```

Po sprawdzeniu zmian uruchom bramki wskazane w `CONTRIBUTING.md` i `docs/PROJECT-WORKFLOW.md`. Test gry z prawdziwym modelem wymaga klucza skonfigurowanego lokalnie; nie zapisuj klucza w repozytorium ani w raporcie.
